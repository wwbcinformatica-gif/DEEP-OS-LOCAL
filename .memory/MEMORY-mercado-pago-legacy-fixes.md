### Mercado Pago API (2026-06-21)
- **API Reference**: `https://www.mercadopago.com.br/developers/pt/reference` — endpoints organized by: Checkout Pro, Checkout Transparente (API Orders), API Payments (legacy), Assinaturas, In-person payments (Point, QR Code).
- **Checkout Pro** (simplest): POST `/checkout-pro/preferences/create-preference` → buyer redirected to MP checkout.
- **Checkout Transparente** (full control): New API Orders model — POST create order → add transactions → process → capture.
- **API Payments (legacy)**: POST create payment directly. Being superseded by API Orders.
- **Auth**: OAuth POST `/oauth_token` for partners; direct token for own apps.
- **PIX token prefix is CRITICAL**: `APPUSR-` (no underscore) → 401 on ALL endpoints. Must be `APP_USR-` (with underscore). Error message "authorization value not present" is misleading.
- **Python SDK**: `mercadopago` v3.2.0 installed. Usage: `mercadopago.SDK(token)` → `sdk.payment().create(payload)`.
- **PIX creation 3-tier fallback**: SDK (`mercadopago_service.py`) → HTTP direct (`pix_utils.py`) → static PIX fallback (`gerar_pix_estatico()`). Both SDK/HTTP silently fall back on failure.
- **Static PIX fallback**: Generated by `gerar_pix_estatico()` in `pix_utils.py`, uses CRC16-CCITT, hardcoded merchant "WBC PDV", city "SAO PAULO". Does NOT link to MP payment tracking.

### Legacy Python/tkinter/electron/Firebird Fixes (completed)
- **Dual config architecture**: Project has TWO separate config systems. Python tkinter app uses `config.json` (via config.py). React frontend uses `preferences.json` (via FastAPI /api/preferences/) + localStorage. They do NOT communicate — theme/sound changes in one don't affect the other.
- **theme_manager.py is in-memory only**: `set_theme()` changes a global variable but never persists. Theme lost on restart. `main.py:_navigate()` re-reads config.json and re-applies, but config.json theme only changes if manually edited.
- **audio.py reads config on init**: `_sound_enabled` and `_volume` now read from config.json in `init()`. Previously hardcoded `_sound_enabled = True`.
- **CTkToplevel + grab_set + messagebox = architectural conflict**: tkinter messagebox creates its own modal grab that conflicts with CTkToplevel's grab_set(). Cannot be fixed with timing hacks. Use inline validation feedback instead (change field border color + error label within form). Fixed by rewriting produto_form.py to use only inline errors.
- **electron/main.js clearStorageData() destroyed all persistence**: `session.defaultSession.clearStorageData()` on every startup wiped localStorage where React saves theme/sound/font/modules. This was THE root cause of "nada salva" in the frontend. Fixed by removing that line.
- **CURRENT_DATE as SQL parameter is a string literal in Firebird**: When `CURRENT_DATE` is passed as a bind parameter (`?`), Firebird treats it as the string `"CURRENT_DATE"` not as the SQL function. Must be embedded directly in the SQL string, not parameterized. Affected `backend/routes/clientes.py:94`.
- **Firebird SQLCODE -303 "conversion error from string"**: Empty strings `""` passed to DATE/INTEGER/NUMERIC columns cause this error. Backend must convert empty strings to `None` (NULL) before passing to Firebird. Affects ALL CRUD routes receiving optional form fields (clientes, produtos, etc.). The CURRENT_DATE fix was only one instance — any non-string column receiving `""` triggers the same error.
