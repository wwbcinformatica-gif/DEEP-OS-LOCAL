## Project context
_What is this project? What's its goal? High-level identity._

## Architecture decisions (WBC-ZERO-G 5.0 expansion)

- **Dual learning on task completion**: `agents/loop.py` calls both `index_task_memory()` (elastic memory) AND `aprender_com_a_tarefa()` (brain.py/FAQ). Elastic memory is primary long-term storage; brain.py provides backward compatibility.
- **Anti-loop is per-lifecycle-execution**: Each `run_lifecycle()` call gets fresh `CircuitBreaker` and `StateHashTracker`. Limits are per-subtask, not global.
- **Planning Toll Enforcement (2026-06-21, IMPLEMENTING)**: Hard enforcement gate in `run_lifecycle()` (lifecycle.py) at the TOOL_CALLS branch. When `step ≤ 2` and model response has `tool_calls` but lacks reasoning text with markdown checkboxes and `task_plan` JSON — BLOCK tool execution. Three files: `lifecycle.py` (validation gate), `chat.py` (prompt injection), `prompts.py` (prompt content).
- **Deterministic fallback for neuron extraction (2026-07-08, IMPLEMENTED)**: `backend/memory/brain.py` rewritten with `_extract_fallback_insight()` and `_extract_structured_fallback()`. When LLM unavailable (placeholder API key, timeout, error), rule-based extraction analyzes tools used, error patterns, and success rate to create neurons. Ensures faq.json is never empty regardless of API key configuration.
- **Circuit breaker limits relaxed (2026-07-08, IMPLEMENTED)**: `loop.py` Anti-Loop limits increased: `max_consecutive_state_hash` 2→3, `circuit_breaker_max_think` 5→8, `circuit_breaker_max_tools` 20→30, `circuit_breaker_max_total` 20→30. Prevents premature task termination that was causing 100% failure-only index entries.
- **FAISS vector memory system (2026-07-09, IMPLEMENTED)**: `backend/memory/vector_memory.py` uses FAISS IndexFlatIP with normalized embeddings for cosine similarity. Model: `paraphrase-multilingual-MiniLM-L12-v2` (384-dim, 50+ languages). Lazy-loads model on first search. Documents stored in `data/memory/vectors/embeddings_cache.json`, FAISS index in `faiss_index.bin`. Knowledge loader (`backend/memory/knowledge_loader.py`) fetches from official docs sites and indexes automatically.
- **Venv must use 64-bit Python for ML**: `C:\DEEP-OS\venv` created with `py -3.11 -m venv venv --clear`. Any scripts or bat files must activate this venv, not the system Python. `start-total.bat` needs updating to use correct venv path.
- **Knowledge loader text extraction is basic**: Uses regex HTML stripping, not a proper parser like BeautifulSoup. Works for documentation sites but may include navigation/footer text and miss JS-rendered content. Consider upgrading if quality is insufficient.

## Correction flow and context preservation (2026-08-05)

- **Interruption/correction flow (2026-08-05, IMPLEMENTED)**: When user sends a message while agent is processing (`loading=true`), frontend aborts the current request, saves conversation context (last 10 msgs), and sends new message with `is_correction: true`. Backend clears the processing state and processes the new message with full context. User sees "⏹️ Tarefa interrompida. Processando correção..." notification.
- **Full context preservation on correction (2026-08-05, IMPLEMENTED)**: Backend always loads 50 most recent messages from database as base context, then appends correction context on top. Agent never loses sight of what happened before the interruption. Works like OpenCode — full conversation history always available.
- **Stuck session recovery (2026-08-05, IMPLEMENTED)**: Backend detects sessions stuck in "processing" state for >60 seconds and auto-clears them. When correction arrives, also clears any queued messages for that session.
- **Queued message system removed from frontend (2026-08-05)**: Old behavior: queue messages in `messageQueueRef` and process after current request finishes. New behavior: abort current request and send fresh. Queue ref still exists but is no longer populated.
- **Jarvis TTS MediaSource fix (2026-08-05, IMPLEMENTED)**: `audio.play()` was called after only 300ms before audio data was buffered, causing browser errors and playback stopping after a few seconds. Fix: wait for first chunk to be appended to `sourceBuffer` (via `updateend` event) before calling `play()`. Also: `audio.onerror` now only kills playback on fatal errors (code ≥ 3), not transient errors. Added `QuotaExceededError` handling in `pump()` to remove old buffered data when buffer is full.
