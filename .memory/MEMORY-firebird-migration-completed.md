# MEMORY-firebird-migration-completed.md
_Firebird→PostgreSQL migration entries that are completed or historical. Extracted from MEMORY.md to reduce token budget._

- **Firebird→PostgreSQL serialization COMPLETED (89 occurrences, 14 files)**: All `SELECT COALESCE(MAX(ID),0)+1` replaced with `INSERT...RETURNING`. Pattern: omit ID from INSERT, append `RETURNING ID_COL`, capture with `cur.fetchone()['id']`. NOT `fetchone()[0]` — RealDictRow is a dict, not a tuple. Per-table column names: `PRODUTOS→ID_PRODUTO`, `CLIENTES→ID_CLIENTE`, `FORNECEDOR→ID_FORNECEDOR`, `CIDADES→CODIGO`, `PAISES→CODIGO`, `PEDIDO_ITENS→ID_ITENS`. Files: pdv.py(5), produtos.py(1), clientes.py(1), caixa.py(4), orcamentos.py(1), financeiro.py(12), admin.py(2), ordem_servico.py(2), auxiliares.py(9), seguranca.py(4), vendas_avancadas.py(12), estoque_avancado.py(13), fiscal_tabelas.py(9), segmentos.py(18). One exception: `segmentos.py` has `COALESCE(MAX(NUMERO)` for document sequence — intentionally kept.
- **run_migrations.py broken on PostgreSQL — FIXED**: `_column_exists()` / `_table_exists()` were rewritten from Firebird `RDB$RELATION_FIELDS`/`RDB$RELATIONS` to PostgreSQL `information_schema.columns`/`information_schema.tables`.
- **Remove license/migration from cloud version**: Firebird-specific `SISTEMA_LICENCA` and `RDB$RELATIONS` don't exist in PostgreSQL. Both startup functions commented out. `licenca_router` removed from main.py.
- **fdb removal COMPLETED (2026-06-23)**: `import fdb` removed from `admin.py` and `seguranca.py`. All `except fdb.DatabaseError` replaced with `except Exception`. Backend is now fully PostgreSQL-compatible at the import level — zero `fdb` references in any route file. `gbak.exe` backup code in `admin.py` replaced with Supabase dashboard stubs.
- **database.py `_execute()` cursor leak FIXED (2026-06-22→23)**: Original code never closed cursor/connection on exception path. Fixed by adding `cur.close()` and `conn.rollback()` in the exception handler before reconnect logic.
- **Migration reference doc**: `MANUAL/firebird-to-postgresql-comandos.md` — complete commands for Firebird→PostgreSQL migration including adapter code, SQL for tables, permissions, error reference.
- **Schema needs barras_cx, gtin, descricao_compra columns**: Backend `ALL_COLS` in `produtos.py` references these columns but original Supabase schema missed them. INSERT with unknown columns causes silent failure → aborted transaction.
- **Template literal fetch calls need separate fix**: First batch script only matches `fetch('/api/` (single-quoted). Template literal calls `fetch(\`/api/\${...}\`)` require different regex. Always check for both patterns after batch operations.
- **pip psycopg2-binary Windows**: Requires `--only-binary=:all:` and version pin `==2.9.9` on Python 3.11-32bit. Unpinned httpx conflicts with supabase — use unpinned requirements.
- **`SKIP` is Firebird OFFSET syntax**: `SELECT FIRST n SKIP m` → `LIMIT n OFFSET m` in PostgreSQL. Used in 20 places across 9 route files. `_adapt_first_to_limit()` updated to handle both `FIRST` and `SKIP`.
- **Supabase SQL Editor timeout on large schemas**: 94-table schema causes "SQL query ran into an upstream timeout". Solution: Python psycopg2 script (`supabase/run_schema.py`) executes SQL directly. 109 commands, 0 errors.
- **supabase/run_schema.py**: Python script to run schema on Supabase directly via psycopg2. Handles Windows cp1252 encoding, splits by semicolons, reports per-statement status.
- **Supabase password URL-encoding**: Database password with `@` requires `%40` in connection URI. psycopg2: `postgresql://postgres:An0n1m0s0204%40@db.jgxqgdfkviqjnbjdjzrj.supabase.co:5432/postgres`
- **Schema mismatch: supabase/schema.sql vs backend**: Schema creates `empresa` (lowercase, `razao_social`, `endereco`) but backend queries `EMITENTE` (uppercase Firebird convention, `RAZ_SOCIAL`, `ENDER`). PostgreSQL lowercases unquoted identifiers but `emitente` ≠ `empresa`. Must create separate tables matching backend column names.
- **Startup migrations must not use undefined names**: FastAPI `@app.on_event('startup')` crashes entire app on `NameError`. Use `print()` or ensure `logger` is imported.
- **PostgreSQL lowercase table naming**: Use lowercase in CREATE TABLE (`emitente`, `contador`). Backend SQL uses uppercase (`EMITENTE`, `CONTADOR`) which PostgreSQL lowercases automatically. Avoids case-sensitivity issues.
