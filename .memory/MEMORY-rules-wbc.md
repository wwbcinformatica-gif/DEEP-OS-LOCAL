# WBC-PDV and WBC-Test Rules
_Historical rules for WBC-PDV 2.0 and WBC-Test projects. Extracted from main MEMORY.md to keep Rules section within budget._

## WBC-PDV 2.0 Rules

- Não adicionar `messagebox` do tkinter em janelas `CTkToplevel` com `grab_set()` — causa conflito de foco. Usar erros inline no próprio formulário.
- **MOVIMENTO totals are application-managed (no triggers)**: `MOVIMENTO.TOTAL_VENDA`, `TOTAL_SUPRIMENTO`, `TOTAL_SANGRIA`, `TOTAL_FINAL` are updated by each endpoint (finalizar_venda, suprimento, sangria, estornar_orcamento). No Firebird triggers exist. Any new operation that affects caixa totals must explicitly UPDATE the MOVIMENTO row. Cancel (status='C') does NOT update MOVIMENTO — only estorno (status='F'→'E') decrements TOTAL_VENDA.
- **Firebird date convention (CORRECTED 2026-06-22)**: DATE/TIMESTAMP columns accept `datetime.now().date()` — the fdb driver handles serialization natively. Using `float()` for DATE columns causes `'float' object has no attribute 'month'` error on read. EXCEPTION: `DOUBLE PRECISION` columns (like `FINANCEIRO_MOV.DT_LANC`/`HR_LANC`) MUST use `float(datetime.now().strftime('%Y%m%d'))` and `float(datetime.now().strftime('%H%M%S'))`. For reading dates from DB, use `_fmt_date()` helper that handles float, datetime.date, datetime.time, and string returns.
- Campos obrigatórios: Nome e Celular em todos os cadastros de cliente.
- Botão Salvar deve ficar desativado quando campos obrigatórios estão vazios.
- Manual do usuario (docs/MANUAL_USUARIO.md) deve ser escrito para leigos — linguagem simples, passo a passo, exemplos praticos. Acessibilidade exige que qualquer pessoa possa usar o sistema.
- Non-required fields must use `None`/NULL, not empty strings `""`: Firebird throws SQLCODE -303 when it receives `""` for DATE/INTEGER/NUMERIC columns. Backend routes must coerce empty form values to `None` before building SQL parameters.

- **Electron 35.7.5 asar integrity check (2026-07-15, CRITICAL)**: The exe contains an integrity hash at offset ~200132415 in format `[{"file":"resources\\app.asar","alg":"SHA256","value":"<hex>"}]`. Patching this hash is NECESSARY but NOT SUFFICIENT — there's a second runtime validation that compares against the asar's binary format/header structure (not just content hash). `@electron/asar` v4.2.0 produces a different format (237 bytes smaller, different header ordering) that fails this second check. To modify an asar, either: (a) use the exact same packer version as the original build, (b) patch the asar binary in-place without repacking, or (c) find and disable the second integrity check. Original installer at `C:\1784061461004_RunTest 1.1.2`.

## Task checklist format

- Task checklist format: `[✓]` done, `[⏳]` or `[⚡]` in-progress, `[ ]` pending. Model emits `task_plan` and `task_progress` JSON events in SSE stream. Frontend renders as real-time checklist. Tasks with 2+ steps MUST use this format.
