## Rules (WBC-PDV 2.0)

- **WBC-PDV 2.0 deploy command**: `npx vercel --prod --yes --archive=tgz` from `C:\WBC-PDV 2.0\frontend-next\`
- **WBC-PDV 2.0 OS vs Orçamento use different tables**: OS uses `ordem_servico`/`ordem_servico_itens`. Orçamento uses `dav`/`dav_itens`. Never assume they share data.

## Architecture decisions (WBC-PDV 2.0)

- Electron `main.js`: NÃO usar `clearStorageData()` — destrói localStorage a cada startup (temas, sons, fonte).
- PIX: O `pix-status` endpoint agora consulta a API do MP diretamente (polling), não depende só do webhook.
- Impressão automática: Ao confirmar PIX (manual ou via polling), abre PrintPreview automaticamente.
- PIX: `MP_ACCESS_TOKEN` DEVE ter prefixo `APP_USR-` (com underscore). `APPUSR-` (sem) causa 401 silencioso e cai no fallback estático.
- **Print model — two approaches**: (1) `PrintPreview` React modal component for ALL in-app documents (DAV, O.S., fiscal DANFE) — works in Electron and browser. (2) `print.js` with `window.open()` + auto-print browser fallback — only works in browser (Electron blocks popups). Fiscal notes MUST use approach (1) via PrintPreview. `print.js` Electron paths (`imprimirCupomSilencioso`/`printHtml`) are only for non-fiscal direct printing. Electron print dialog (native) must NEVER open for fiscal notes.
- **Fiscal DANFE uses PrintPreview, not print.js**: FiscalDashboard imports PrintPreview with `isFiscal={true}` prop. FiscalContent component renders DANFE layout (NFC-e/NFe header, Destinatário, Dados Fiscais, Produtos, Totais). NFE/NFCE table IDs ≠ DAV IDs — cannot fetch from `/api/orcamentos/{id}`, must use data from fiscal listing directly.
- **DANFE format reference (NotaCompraEspelho.pdf)**: Standard Brazilian DANFE with: empresa header + NF-e box (Número, Série, Modelo), chave de acesso, Dados do Fornecedor, Cálculo do Imposto (ICMS columns), Produtos e Serviço (15+ columns: CST/CSOSN, BC ICMS, VL ICMS, VL PIS, VL COFINS, etc.), "ESPELHO DA NOTA FISCAL SEM VALOR FISCAL" watermark for homologação.
- **Texto em Maiúsculas — two-tier design**: Global toggle (`wbc-texto-maiusculo`) affects theme text only (labels, headers, sidebar — excludes inputs). Per-module toggles (`wbc-maiusculo-{modulo}`) affect both table display AND form inputs. CSS uses `html.wbc-maiusculo-*` selectors for higher specificity. Modules: Produtos, Clientes, O.S., Orçamentos, Vendedores.
- **WBC-PDV 2.0 OS print two-copy layout (IMPLEMENTED)**: Print template renders two copies on same A4 page. Top half = Via do Cliente (header + client + equipment + relato + items + total + obs + signature). Dotted line separator: "✂ Corte aqui". Bottom half = Via da Loja (same + user section + larger signature).
