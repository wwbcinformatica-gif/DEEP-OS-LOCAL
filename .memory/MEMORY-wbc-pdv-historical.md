# WBC-PDV 2.0 — Historical Discovered Knowledge
_Older entries extracted from MEMORY.md to stay under token budget. These are deployed/stable and unlikely to be revisited._

### Discovered (Historical)

- **WBC-PDV 2.0 bug: OS totals R$ 0,00 in print (2026-07-03, FIXED)**: OS print view shows correct per-item values but summary section (Peças, Serviços, Valor Total) renders R$ 0,00. Print template read `detalhe.total_pecas` etc. directly from DB record fields. These were never populated. **FIX APPLIED & DEPLOYED**: Added `calcularTotais()` function that computes totals from items array, spreading result into detalhe object on load. Classifies items as parts vs services by product name keywords.
- **WBC-PDV 2.0 OS vs Orçamento use different tables (CONFIRMED)**: OS uses `ordem_servico`/`ordem_servico_itens`. Orçamento uses `dav`/`dav_itens`. They are separate tables, not the same table with different modes. User initially suspected they shared a table.
- **WBC-PDV 2.0 Orçamento single Edit button (2026-07-03, DEPLOYED)**: Replaced 3 separate buttons (Editar Itens, Alterar Situação, Editar Obs) with single "✏️ Editar" opening full modal. State vars: `editandoCompleto`, `editCompletoForm`, `editCompletoItens`, `editCompletoCliente`. Functions: `abrirEditarCompleto`, `buscarProdutoEdit`, `selProdutoEdit`, `salvarEditarCompleto`. Also removed `.eq("tenant_id", tenantId)` from all update/select/delete queries.
- **WBC-PDV 2.0 OS print two-copy layout (2026-07-03, DEPLOYED)**: Print template now renders two copies on same A4 page separated by dotted line. Top = Via do Cliente, Bottom = Via da Loja (with user section + larger signature).
- **WBC-PDV 2.0 `usePersistState` localStorage causes delete confusion (2026-07-03)**: `wbc_os_draft` key preserves ServicoForm items across page navigation. When items are deleted from detail view, DB is updated but localStorage still holds old items. Navigating to "Serviço" tab loads from draft, making it appear delete didn't work. Fix: clear draft when items are modified from detail view. User confirmed draft behavior is desired: "isso mesmo que eu falei para guardar o que foi digitado".
- **WBC-PDV 2.0 `.eq("tenant_id", tenantId)` causes silent query failures (2026-07-03)**: If `tenantId` is null/empty or doesn't match stored value, queries return no rows silently. Removed from update/delete/select operations in both O.S. and Orçamento pages. User must ensure tenantId is properly set before these filters are safe to use.
- **WBC-PDV 2.0 `ordem_servico_itens` RLS DELETE blocker (2026-07-03, FIXED)**: RLS was enabled on `ordem_servico_itens` and `dav_itens` WITHOUT DELETE policies. Supabase silently blocked all DELETE operations on these tables. Fix: added DELETE policies (`auth.role() = 'authenticated'`) for both tables via `fix_rls_itens_delete.sql`. This was the REAL root cause of "delete not persisting" — NOT the localStorage draft issue initially suspected.
- **WBC-PDV 2.0 Endereço tab (2026-07-03, DEPLOYED)**: Added "Endereço" tab to both O.S. and Orçamento pages. O.S. = basic address (endereco, numero, complemento, bairro, cidade, UF, CEP, pais + contatos). Orçamento = full address + dados adicionais (nome fantasia, data nascimento, sexo, site, condição pagamento, limite crédito). User clarified: "na O.S é breve cadastro rapido o cadastro completo vai ficar em orçamento".
- **WBC-PDV 2.0 Edit modal now uses ClienteForm (2026-07-03, DEPLOYED)**: Replaced custom edit forms in both O.S. and Orçamento with shared `ClienteForm` component. This gives edit modal the same tabbed layout ("Dados Pessoais" and "Endereço") as the create modal. Field mapping required: DB uses `_cliente` suffix (e.g., `nome_cliente`), ClienteForm expects without suffix (e.g., `cliente`). Both `abrirEditarCompleto` and `onSave` callbacks map between formats.
- **WBC-PDV 2.0 Converter em Venda flow (2026-07-03, DEPLOYED)**: Added "Converter em Venda" button to both O.S. and Orçamento detail views. Button navigates to PDV with query param: `/dashboard/pdv?orcamento=ID` or `/dashboard/pdv?os=ID`. PDV useEffect detects query params and loads items from respective tables. BUG: Items show total but cart table empty — needs investigation.
- **WBC-PDV 2.0 PDV cart structure (2026-07-03)**: Cart items: `{ id_produto, produto, valor_unitario, quantidade, barras, estoque, desconto_pct }`. DAV table uses `modo` field: `"O"` for orçamento, `"V"` for venda. O.S. uses separate `ordem_servico`/`ordem_servico_itens` tables.
- **WBC-PDV 2.0 PDV phone fallback logic (2026-07-03)**: When loading orçamento/O.S. into PDV, phone field uses `fone_cliente || celular_cliente || whatsapp_cliente` — picks whichever is filled. This matters because PDV only has one contact field.
- **WBC-PDV 2.0 sessionStorage anti-reload pattern (2026-07-03)**: `sessionStorage.setItem("wbc_pdv_loaded_${id}", "1")` prevents PDV from re-loading the same orçamento/O.S. when user navigates away and back. Cleared in `novaVenda()`. This replaced `useRef(false)` which reset on unmount.
- **WBC-PDV 2.0 `useRef` vs `sessionStorage` for one-shot flags**: `useRef` resets on component unmount — unsuitable for preventing re-loads across navigation. `sessionStorage` persists across the browser tab lifetime. Use sessionStorage for flags that must survive navigation within same tab.
- **WBC-PDV 2.0 Detail section overflow pattern (2026-07-04)**: Both O.S. and Orçamento detail areas use `shrink-0` on the detail container, preventing scrolling within the flex parent. When content exceeds viewport, bottom sections are cut off. Fix: wrap detail content in a div with `overflow-y-auto flex-1 min-h-0`.
- **WBC-PDV 2.0 Responsive CSS media queries (2026-07-04, DEPLOYED)**: Added breakpoints in `globals.css`: Tablet ≤1024px (2-col grids), Mobile ≤768px (single-col, 44px inputs, full-screen modals, scrollable tabs), Small ≤480px (all single-col, stacked buttons). iPhone safe area via `@supports (padding-top: env(safe-area-inset-top))`.

### Dead ends
- Python string-splicing on JSX files: `content.find()` matched wrong occurrence, destroyed file structure (129 TS errors). Recovery: `git checkout HEAD -- <file>`. Never use Python scripts for JSX modifications.
- **DANGER: Python string-splicing on JSX files (2026-07-03)**: Using `content.find()` to locate and remove duplicate sections in JSX is extremely fragile. Same patterns (function names, component definitions) can appear multiple times in a file — the script matched the wrong occurrence and destroyed `ordem_servico/page.tsx` (129 TS errors). Always use the Edit tool for JSX modifications, or verify line numbers with grep before bulk operations.
